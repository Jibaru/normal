# WasenderAPI, Meta, and WhatsApp: Primary-Source Notes

**Research cutoff and access date:** 2026-07-30

**Scope:** First-party WasenderAPI, Meta, and WhatsApp documentation only. No community reports, reseller claims, or reverse-engineering projects are used. This is a factual baseline for a later self-hosted-service assessment, not a survey of self-hosted candidates or legal advice.

## Labels

- **Fact:** Directly stated in a cited first-party source.
- **Absent:** Information was not found in the reviewed first-party public material. This is not proof that it does not exist privately.
- **Conflict:** First-party pages disagree or leave materially inconsistent guidance.
- **Inference:** A conclusion derived from cited facts, not an explicit vendor statement.

## Decision-Critical Summary

- **Fact:** WasenderAPI's public product is a hosted subscription API whose "session" is one WhatsApp account connected as a linked device by scanning a QR code in **WhatsApp > Settings > Linked Devices**; QR is the default connection method and Passkey is also documented. It exposes one-to-one messaging, contacts, groups, and channels through session-scoped APIs and webhooks. [W2] [W3] [W5]
- **Fact:** Meta Cloud API is also hosted, but by Meta. Meta says it hosts and maintains the API and removes the former requirement to operate Business API containers. Access to the API itself is free; billable message delivery is separate. [M2]
- **Fact:** Meta Cloud API uses a business identity model: Meta app -> business portfolio -> WhatsApp Business Account (WABA) -> registered business phone number, with access tokens and permissions. It is not a QR-linked personal WhatsApp Web session. [M1] [M3] [M4]
- **Fact:** Meta now offers a Groups API. Historical statements that Cloud API has no group support are obsolete. Current Groups API access requires an Official Business Account (OBA), groups are invite-only, the documented maximum is 8 participants, and a business number may create up to 10,000 groups. Groups are unavailable to WhatsApp Business app/Coexistence phone numbers. [M8] [M10]
- **Inference:** Meta Cloud API cannot replace QR-linked personal-account behavior or access to an account's existing ordinary groups. It can replace a first-party business-messaging use case only if the product can adopt registered business numbers, 24-hour customer-service-window/template rules, and either one-to-one conversations or new, OBA-only, 8-participant API-created groups. [M4] [M5] [M6] [M7] [M8]
- **Inference:** Neither reviewed offering satisfies a strict "self-hosted WhatsApp service" requirement: Meta explicitly hosts Cloud API, while WasenderAPI only documents its hosted SaaS endpoints and subscriptions and provides no public self-host package or deployment guide. [M2] [W1] [W2]
- **Fact:** WhatsApp's official unofficial-app FAQ says, "Using these apps or linking your WhatsApp account to unofficial versions of WhatsApp violates our Terms of Service." It warns that users may see messages saying they need the official app or have been logged out for using an unofficial app. [L1]
- **Fact:** The ordinary WhatsApp Terms shown to non-European-region users prohibit impermissible bulk messaging, auto-messaging, non-personal use unless authorized, unauthorized automated access, reverse engineering, and unauthorized third-party APIs that function substantially like the service. They permit account suspension or termination for violations. [L2]
- **Scope distinction:** The WhatsApp Business Solution Terms govern the WABA-based WhatsApp Business Solution and were last modified 2026-03-06. Their Business Solution Data and AI Provider restrictions are material to a Meta Cloud API redesign, but the document does not purport to govern an ordinary QR-linked account merely because an AI product can access that account. Counsel must analyze the governing account, product, territory, and terms separately. [L2] [L3]

## 1. WasenderAPI

### Product and Session Model

- **Fact:** A session represents one WhatsApp account/number connected to WasenderAPI. Every session requires a unique phone number. Multiple accounts are represented as multiple simultaneous sessions, constrained by the subscription's session count. [W2] [W3] [W11]
- **Fact:** Normal onboarding is linked-device onboarding: create a session, display a QR code, and scan it from the phone's Linked Devices screen. The connection API defaults to `linkMethod: "qr"`; `"passkey"` is an alternative using WasenderAPI's Device Link Helper flow. [W3] [W5]
- **Fact:** Documented states are `connecting`, `connected`, `disconnected`, `need_scan`, `need_passkey`, `logged_out`, and `expired`. Disconnected, logged-out, or expired sessions require reconnect/relink handling. [W5]
- **Fact:** Authentication is split by scope. A Personal Access Token (PAT) controls account-level operations such as listing, creating, and deleting sessions. Once connected, each session receives a separate API key used for session operations and messaging; deleting the session invalidates that key. [W4]
- **Fact:** A first-party WasenderAPI article published 2026-07-17 says the managed service handles "the underlying Baileys socket connections," auto-reconnect logic, and state management. The article describes Baileys as a library that reverse-engineers the WhatsApp Web WebSocket protocol. [W12]
- **Inference:** The QR flow, Linked Devices instructions, session lifecycle, WhatsApp JIDs, visibility of the account's groups/contacts, and WasenderAPI's Baileys statement support treating it as a managed WhatsApp Web linked-device service. The public material does not identify the Baileys version or fork or disclose enough implementation detail to infer its complete production topology. [W2] [W3] [W5] [W12]

### Documented API Surface

The official API index is the most complete endpoint inventory reviewed. [W2]

| Area | Documented routes/capabilities |
| --- | --- |
| Account/session lifecycle | `GET/POST /api/whatsapp-sessions`, `GET/PUT/DELETE /api/whatsapp-sessions/{session}`, plus `/connect`, `/restart`, `/qrcode`, `/passkey-token`, `/disconnect`, `/message-logs`, `/session-logs`, and `/regenerate-key`; session-scoped `GET /api/status`, `GET /api/user`, number lookup, and presence updates. |
| Sending and message actions | `POST /api/send-message` for text, image, video, document, audio/voice note, sticker, contact, location, quoted replies, polls, mentions, and view-once media. Separate routes resend failed messages, get message info, edit, delete, and mark read. |
| Contacts | List/get contacts, profile pictures, create/update, block/unblock, check whether a number is on WhatsApp, and resolve phone-number JIDs to/from LIDs. |
| Groups | Create/list groups; get metadata, participants, and pictures; send messages and mentions; add/remove/promote/demote participants; update settings; obtain/inspect/accept invite links; and leave groups. Admin privileges are required for relevant mutations. |
| Channels | The public index documents sending to an existing channel/newsletter JID through `/api/send-message`; it does not document a comparably complete channel-management API. |
| Media | `POST /api/upload` accepts binary or Base64 uploads; `POST /api/decrypt-media` decrypts incoming WhatsApp media. |
| Webhooks | Incoming/all/direct/group/newsletter messages, sent/status/receipt/delete/reaction/poll events, contacts, chats, groups and participants, calls, QR/Passkey updates, and session status. |

Additional documented media facts:

- **Fact:** WasenderAPI-hosted uploads are made available through a public URL for 24 hours. The upload endpoint documents limits of 100 MB for documents, 16 MB for images, 50 MB for video, 16 MB for audio, and 5 MB for stickers. [W10]
- **Fact:** Incoming media can arrive encrypted with a URL and media key. The decrypt endpoint returns a public URL valid for one hour; the docs also provide client-side decryption examples. [W10]
- **Fact:** Message logs cover messages sent using the API and require message logging to be enabled. They are not documented as a complete synchronized history of every chat. [W2]

- **Fact:** Paid plans advertise unlimited contacts, no daily message cap, full API access, and real-time webhooks. The page advertises 15% savings for yearly billing but the reviewed public markup did not expose final annual checkout totals. [W1]
- **Fact:** The trial is 3 days. Rate-limit documentation caps trial sending at 1 request/minute and 50/day. [W1] [W6]
- **Fact:** Paid `send-message` traffic is documented at 256 requests/minute per endpoint per session with no daily send-message cap. Enabling account protection overrides this with 1 send request per 5 seconds. [W6]
- **Fact:** Paid group-participant/metadata reads are capped at 10/minute and 500/day; contact-picture and number-existence checks are capped at 60/minute and 1,000/day. [W6]
- **Fact:** A global concurrent-request cap exists per session, but its numeric value is not published. WasenderAPI recommends queues with 1 to 5 concurrent workers per session. [W6]
- **Fact:** Fees exclude taxes, prices may change on 30 days' notice, and higher-volume/custom economics are not public. [W8]
- **Inference:** "Unlimited messages" means no daily subscription-meter cap, not unlimited safe throughput or guaranteed delivery. Endpoint rate limits, session connection state, WhatsApp anti-abuse enforcement, consent rules, and WasenderAPI's own suspension rights still constrain use. [W6] [W8]

### Webhooks

- **Fact:** A session can be configured with one publicly accessible HTTPS webhook URL and selected event subscriptions. The docs tell receivers to acknowledge quickly with HTTP `200`. [W7]
- **Fact:** The optional webhook secret is sent in `X-Webhook-Signature`. The official example validates it by direct string equality with the stored secret; it does not describe an HMAC over the payload. [W7]
- **Fact:** `messages.received` is incoming-only, while `messages.upsert` covers incoming and outgoing messages. Dedicated direct, group, and newsletter receive events are also documented. Group participant, group metadata, status/read receipts, calls, reactions, polls, QR, Passkey, and session-state events are available. [W2] [W7]
- **Fact:** A first-party marketing article says WasenderAPI has built-in message queueing and "robust webhook delivery systems" and claims that, if an endpoint goes down, the platform retries automatically, "ensuring zero data loss." [W12]
- **Absent:** Neither that article nor the reviewed public webhook docs specifies retry duration/schedule, maximum attempts, backoff, response-code treatment, duplicate-delivery semantics, event ordering, replay/dead-letter behavior, queue durability, payload-size limits, or mTLS. No contractual webhook-delivery guarantee or SLA was located; "zero data loss" is an unquantified marketing claim. [W7] [W12]
- **Conflict:** The setup prose calls creation of a webhook secret optional, while its parameter table marks `X-Webhook-Signature` required. [W7]

### Terms, Privacy, and Official Caveats

- **Fact:** WasenderAPI states that it is not supported, endorsed, or affiliated with WhatsApp. Users accept the risk of WhatsApp account bans or restrictions and disruption from WhatsApp API, policy, software, or security changes. [W8]
- **Fact:** Customers must comply with WhatsApp terms/policies and applicable law, and must obtain prior consent from every recipient. Spam and bulk messages are prohibited despite the commercial "unlimited" plan wording. [W8]
- **Fact:** WasenderAPI may determine that API usage is abusive/excessive and temporarily or permanently suspend API access. It may modify or discontinue the service, and provides it "as is" and "as available." [W8]
- **Fact:** The privacy policy says WasenderAPI collects message content, recipient information, and usage statistics and may share information with service providers for hosting, processing, analytics, support, and related functions. [W9]
- **Fact:** Terms disclaim direct and consequential damages. The reviewed terms and privacy pages both display `Last Updated: January 1, 2023`; the separate refund policy displays `Last Updated: May 1, 2025`. [W8] [W9]
- **Conflict:** Cancellation language is inconsistent. The subscription help says canceled service continues to the end of the billing period, while the terms say cancellation takes effect immediately and account content is immediately deleted. Initial-purchase refund language provides a 7-day window with exceptions, while the help page broadly says canceled subscriptions are non-refundable. Confirm contract behavior before relying on either path. [W8] [W11]
- **Absent:** No public self-host distribution/license, source package or deployment guide, detailed production topology, exact Baileys version/fork, numeric uptime/latency SLO, commercially binding SLA, disaster-recovery target, contractual webhook-delivery guarantee, data-residency commitment, message-retention schedule, or public DPA was located in the reviewed WasenderAPI pages.

## 2. Meta WhatsApp Cloud API

### Hosting, Identity, and Onboarding

- **Fact:** Meta hosts and maintains Cloud API and provides the incoming/outgoing WhatsApp endpoint. Meta says this removes the need to run Business API containers and their associated operational responsibilities. Cloud API itself has no access fee. [M2]
- **Fact:** A business portfolio is mandatory and contains one or more WABAs. A WABA represents the business and contains phone numbers, usernames, and analytics. A registered business phone number is the send/receive identity. [M1]
- **Fact:** Basic direct onboarding creates a Meta app with the WhatsApp use case, associates it with a business portfolio and WABA, adds a phone number, and uses its phone-number ID in Graph API calls. Production access normally uses a system-user token with `business_management`, `whatsapp_business_messaging`, and `whatsapp_business_management` permissions. [M3]
- **Fact:** A valid business phone number must be owned by the business, have a country/area code, and receive SMS or voice verification. Adding/verifying a number and registering it for Cloud API are separate steps; registration sets a two-step-verification PIN. [M4]
- **Fact:** Newly created business portfolios initially have a cap of 2 registered business numbers. Verification or reaching a 2,000-user messaging limit automatically raises the documented cap to 20. [M4]
- **Fact:** A registered Cloud API number cannot simultaneously be used with consumer WhatsApp Messenger. An existing Messenger account must be deleted before its number is registered. [M4] [M5]
- **Fact:** A WhatsApp Business app number can either be deleted/migrated, losing its existing messaging history and Business app use, or onboarded through a partner supporting Business app onboarding/"Coexistence." [M5] [M6]

### One-to-One Conversation Model

- **Fact:** A user message or call opens or refreshes a 24-hour customer service window (CSW). During it, the business can send free-form service messages. After it closes, the business can only initiate with pre-approved templates. User opt-in is required. [M7]
- **Fact:** `recipient_type` is `individual` for one-to-one messages and `group` for Groups API messages. A successful send response means accepted, not delivered; delivery is reported through webhooks. [M7]
- **Fact:** Cloud API supports text, image, video, audio, documents, contacts, locations, stickers, reactions, contextual replies, typing indicators, read receipts, and several interactive/Flow message types in supported one-to-one contexts. [M7]
- **Fact:** Newly created portfolios can deliver business-initiated messages outside CSWs to 250 unique users in a rolling 24-hour period. Limits can scale to 2,000, 10,000, 100,000, and unlimited based on verification or delivered volume, quality, and utilization criteria. Limits are portfolio-wide across its numbers. [M12]
- **Fact:** The platform overview documents default business-phone throughput of up to 80 messages/second and automatic scaling within applicable limits. [M1]

### Current Groups API and Its Limits

- **Fact:** Groups API access is open to businesses with an Official Business Account (OBA), not to every Cloud API account. Groups are invite-only; users join through an invite link generated/sent by the business. [M8]
- **Fact:** Quick limits are 8 participants per group, 10,000 groups per business number, and at most one Cloud API business in a group. Supported payloads are text, media, text-based templates, and media-based templates. [M8]
- **Fact:** Groups API is unavailable for WhatsApp Business app/Coexistence numbers and numbers onboarded to Multi-solution Conversations. [M8]
- **Fact:** Calling, disappearing messages, view-once, authentication, commerce, and interactive messages are unsupported in groups. Editing/deleting messages and hiding the participant list are also unsupported. [M8]
- **Fact:** To qualify for OBA application, the business must comply with policy, have been on the Business Platform at least 30 days, have a verified business portfolio, enable two-step verification, and have an approved display name. Meta does not grant OBA status to WhatsApp Business app numbers, employees, or test accounts; an application can be rejected. [M10]
- **Fact:** Group-template performance metrics are unavailable. Meta recommends separate group templates rather than reusing one-to-one templates. [M8]
- **Inference:** Groups API is a narrow new-group collaboration feature, not an API bridge into arbitrary groups already visible to a personal or Business app account. Meta describes API-created groups, responses identify a "group made using the Groups API," and the documented management API has no import/attach-to-existing-group operation. [M7] [M8]

### Business App Coexistence Is Not Group Coexistence

- **Fact:** Coexistence requires the customer to use the WhatsApp Business app, while the integrator must be a Solution Partner or Tech Provider using Embedded Signup with session logging and working webhooks. It is not available for consumer WhatsApp Messenger accounts. [M6]
- **Fact:** Coexistence mirrors one-to-one messages between Business app and Cloud API, can synchronize contacts, and can synchronize up to the most recent 180 days of one-to-one history with permission. [M6]
- **Fact:** Existing group chats remain usable in the Business app but are not supported or synchronized to Cloud API. Group-chat messages are excluded from history synchronization. Channels, broadcast lists, and various Business app tools also are not exposed through Cloud API coexistence. [M6]
- **Fact:** Coexistence numbers have fixed throughput of 20 messages/second. Cloud API messages remain subject to Cloud API pricing and its 24-hour CSW; messages sent directly in the Business app remain free and do not open or extend the API's CSW. [M6]
- **Fact:** Onboarding initially unlinks companion apps, after which supported companions can be relinked. Messages sent from supported apps generate `smb_message_echoes` webhooks; unsupported companion behavior has documented gaps. [M6]

### Pricing and Billing as of 2026-07-30

- **Fact:** Since 2025-07-01, ordinary Cloud API messaging uses per-message pricing, not conversation-based pricing. Meta charges only when a template message is delivered. Rate depends on template category, recipient country calling code, and, for eligible categories, volume tier. [M11]
- **Fact:** Non-template messages are free but can only be sent within an open CSW. Utility templates delivered in an open CSW are free. Marketing templates are generally charged. All message types are free during a qualifying 72-hour free-entry-point window. [M11]
- **Fact:** Utility and authentication templates can receive lower volume-tier rates. Tier accrual is monthly, market/category-specific, portfolio-wide across owned WABAs, and counts charged messages only. [M11]
- **Fact:** The current official rate cards are effective 2026-07-01 in the WABA timezone. They are published by currency and country/region. Meta had announced 2026-10-01 market/rate changes but stated that final affected rates would be announced no later than 2026-09-01, so any forecast crossing October needs a sensitivity update. [M11]
- **Fact:** Cloud API billing is handled in Meta Business Suite. Partner/BSP, application, webhook, storage, and support costs are outside Meta's published message-rate formula. [M11]
- **Fact:** Groups use per-message pricing, but a billable group message is charged once for each group member to whom it is delivered, at that recipient's country/category rate. Group utility messages do not qualify for volume tiers. [M9]
- **Fact:** A message from any group member opens/refreshes a CSW for the entire group. [M9]
- **Conflict:** The Groups pricing page says in one paragraph that marketing templates are free inside a group CSW, but its own detailed `pricing.type` definitions identify only utility templates and non-template messages as `free_group_customer_service`; the main pricing page says marketing templates are charged. A conservative cost model should count delivered group marketing templates as billable until Meta confirms otherwise. [M9] [M11]
- **Conditional fact:** Meta has a separate 2026 policy for providers of general-purpose AI assistants and similar AI/ML services. If the service qualifies as an "AI Provider," special use restrictions and per-delivered non-template pricing can apply in legally mandated markets; the current page continues to list Brazil after the temporary European charges ended on 2026-05-12. Applicability must be determined from the product and current terms rather than assumed. [M16]

No numeric Meta country/category rates are copied into these notes because there is no single universal rate and the official matrices are mutable. Use the effective 2026-07-01 currency rate card linked from [M11] with the actual recipient distribution.

### Webhooks

- **Fact:** Meta sends JSON webhooks for inbound messages, outbound statuses, account/capability changes, template state/quality, Coexistence history/contact/echo events, and other subscribed WABA fields. `whatsapp_business_messaging` is required for message webhooks; `whatsapp_business_management` is required for the other fields. [M13]
- **Fact:** Production requires a public callback accepting GET and POST with a valid TLS/SSL certificate; self-signed certificates are unsupported. GET verification compares a chosen verify token and returns `hub.challenge`. [M14]
- **Fact:** POST authenticity uses `X-Hub-Signature-256`, an HMAC-SHA256 over the raw payload using the Meta app secret. Optional mTLS is supported. [M14]
- **Fact:** Payloads can be up to 3 MB. Non-`200` delivery is retried with decreasing frequency for up to 7 days, retries can create duplicates, and receivers must deduplicate. POSTs may batch up to 1,000 updates, but batching is not guaranteed. [M13] [M14]
- **Fact:** Meta provides no historical-webhook retrieval API; receivers must capture and persist required payloads. [M14]

### Media

- **Fact:** The official media lifecycle uses `POST /PHONE_NUMBER_ID/media` to upload, `GET /MEDIA_ID` to obtain a download URL, `GET /MEDIA_URL` with an access token to download, and `DELETE /MEDIA_ID` to delete. Incoming media webhooks include media IDs/URLs. [M15]
- **Fact:** Business-uploaded media is encrypted and persists for 30 days unless deleted. Uploaded media IDs expire after 30 days; incoming webhook media IDs are downloadable for 7 days. Generated media URLs expire after 5 minutes and require an access token. [M15]
- **Fact:** Current documented limits include 100 MB documents, 16 MB audio, 5 MB images, 16 MB video, and 100 KB static/500 KB animated stickers; the overall incoming-media ceiling is 100 MB. [M15]

### Can Cloud API Replace QR-Linked Personal/Group WhatsApp Web Behavior?

| Required behavior | Direct first-party answer |
| --- | --- |
| QR-link any user's personal WhatsApp account as a companion | **No.** Cloud API registers a business phone number. Existing consumer Messenger use must be deleted; the platform has no equivalent personal linked-device session API. [M4] [M5] |
| Continue using the same consumer Messenger number and history | **No.** The Messenger account must be deleted before registration. [M5] |
| Continue using a WhatsApp Business app number for one-to-one chats | **Conditional.** Coexistence supports this through a Solution Partner/Tech Provider flow and mirrors supported one-to-one traffic. It is not ordinary direct QR onboarding. [M6] |
| Read/send in that account's existing group chats | **No.** Coexistence explicitly does not synchronize groups, and Groups API is unavailable on Business app phone numbers. [M6] [M8] |
| Create new API-native group conversations | **Conditional.** Requires OBA, invite-only membership, maximum 8 participants, one Cloud API business, and the documented message/action restrictions. [M8] [M10] |
| Operate the WhatsApp transport on self-hosted infrastructure | **No.** Meta hosts and maintains Cloud API. The application and webhook receiver can be self-hosted, but the WhatsApp transport cannot. [M2] |

**Inference:** Meta is a first-party replacement for compliant business messaging, not a protocol-compatible replacement for WasenderAPI's linked-device account surface. If existing personal numbers, arbitrary existing groups, or QR onboarding are hard requirements, Meta fails functional parity before cost is considered. If those requirements can be replaced by business numbers and one-to-one/template messaging, Meta becomes a viable first-party option with a different operating and cost model.

## 3. WhatsApp Legal and Policy Scope

This section records decision-relevant source text and scope boundaries. It does not decide enforceability, authorization, or the legal classification of a particular gateway.

### Ordinary and QR-Linked Accounts

- **Fact:** WhatsApp's official FAQ defines unofficial apps or websites as third-party "fake WhatsApp apps" and states: "Using these apps or linking your WhatsApp account to unofficial versions of WhatsApp violates our Terms of Service." WhatsApp says it does not support them because it cannot validate their security or privacy practices. [L1]
- **Fact:** The FAQ says an unofficial-app user may receive a system message stating "You need the official WhatsApp to log in" or "You have been logged out for using an unofficial app," and directs users to remove unofficial apps and register with an official WhatsApp app. [L1]
- **Fact:** The ordinary Terms page reviewed displays an effective date of 2021-01-04 and directs European Region users to separate terms. The governing version therefore depends on the user's territory and must be checked for the actual account population. [L2]
- **Fact:** Under "Acceptable Use Of Our Services," the reviewed ordinary Terms require legal, authorized, and acceptable use. They prohibit illegal or impermissible bulk messaging, auto-messaging, auto-dialing, and non-personal use unless WhatsApp otherwise authorizes it. [L2]
- **Fact:** Under "Harm To WhatsApp Or Our Users," the reviewed ordinary Terms prohibit impermissible or unauthorized automated access, reverse engineering, unauthorized collection, unauthorized resale, and creating software or APIs that function substantially the same as WhatsApp and are offered to third parties without authorization. [L2]
- **Fact:** The reviewed ordinary Terms say WhatsApp may disable or suspend an account for Terms or policy violations and may modify, suspend, or terminate access at any time for reasons including harm, risk, or possible legal exposure. [L2]
- **Inference/legal question:** The FAQ is direct first-party evidence that unofficial linked-account use can violate WhatsApp's Terms and lead to loss of account access. Whether a particular hosted linked-device gateway, library, deployment topology, and customer use falls within each clause is a counsel question, not something an open-source license or vendor disclaimer can answer. WasenderAPI's own terms cannot grant authorization from WhatsApp. [L1] [L2] [W8]

### WABA-Based WhatsApp Business Solution

- **Fact:** The WhatsApp Business Solution Terms state that Meta distributes the "WhatsApp Business Solution" under those terms, incorporate the WhatsApp Business Terms of Service, and describe setup and administration of a WABA. The page displays `Last Modified: March 6, 2026`. [L3]
- **Fact:** Those terms require use in compliance with Meta's technical/product documentation and the WhatsApp Business Messaging Policy and regulate Third Party Service Providers and Business Solution Data. [L3]
- **Fact:** The terms contain a specific "AI Providers" clause. It restricts providers and developers whose primary functionality is covered AI/ML technology, includes territory-specific exceptions, permits retaining an AI Provider as a Third Party Service Provider subject to the terms, and restricts using Business Solution Data to create, develop, train, or improve AI models, with a bounded exclusive-use fine-tuning exception. [L3]
- **Scope distinction:** These provisions are relevant when evaluating Meta Cloud API or another WABA-based Business Solution. They must not be imported as though they automatically govern ordinary consumer or Business App accounts linked through an unofficial companion implementation. The ordinary Terms, applicable regional version, unofficial-app guidance, any business-facing terms, and the exact product/deployment model require separate counsel analysis. [L1] [L2] [L3]

## 4. Cost-Model Variables and Formulas

### WasenderAPI

Let `S` be required simultaneously connected WhatsApp numbers. Based on public monthly pricing: [W1]

```text
P_W(S) = 0                    if S = 0
         6 USD/month          if 1 <= S <= 1
         15 USD/month         if 2 <= S <= 3
         30 USD/month         if 4 <= S <= 6
         45 USD/month         if 7 <= S <= 10
         Q_W(S)               if S > 10 (custom quote)
```

If the advertised 15% annual discount applies uniformly at checkout:

```text
Annual subscription estimate = 12 * P_W(S) * 0.85
```

Do not treat that as a quoted annual invoice; validate checkout, taxes, and custom terms.

```text
Monthly Wasender total = P_W(S)
                       + S * proxy_cost_per_session
                       + application_and_webhook_infrastructure
                       + monitoring/support/operations
                       + applicable_tax
```

Provider message-volume term is `0` under the advertised plans, but capacity and risk are not zero-cost variables. Model expected send rate per session against 256 requests/minute, or 12/minute with account protection, plus endpoint-specific daily limits, reconnection labor, and WhatsApp enforcement loss exposure. [W6] [W8]

### Meta Cloud API

Let:

- `D[c,k,t]` = delivered, billable one-to-one template messages to country/rate region `c`, category `k`, and volume tier `t`.
- `R[c,k,t]` = current official rate in the WABA billing currency.
- `DG[c,k]` = billable group-message deliveries to individual group recipients in region `c`, category `k`.
- `RG[c,k]` = group rate, documented as the corresponding one-to-one per-message rate; group utility has no volume tiers.
- `DAI[c]` and `RAI[c]` = delivered non-template AI-provider messages and rate, only if the special AI-provider policy applies.
- `C_partner`, `C_app`, and `C_ops` = optional partner/BSP, application/webhook/storage, and operating costs.

```text
C_meta_1to1 = sum over c,k,t (D[c,k,t] * R[c,k,t])

C_meta_groups = sum over c,k (DG[c,k] * RG[c,k])

C_meta_AI = sum over applicable c (DAI[c] * RAI[c])

Monthly Meta total = C_meta_1to1
                   + C_meta_groups
                   + C_meta_AI
                   + C_partner
                   + C_app
                   + C_ops
                   + applicable_tax
```

Set message cost to zero for ordinary non-template messages in an open CSW, utility templates in an open CSW, and all messages in a qualifying free-entry-point window. Do not set marketing templates to zero except where the official rule is unambiguous; use the conservative group treatment noted under the pricing conflict. [M9] [M11]

For groups, count recipient deliveries, not API calls:

```text
Cost of one billable group send
  = sum over recipients actually delivered (rate for recipient country/category)
```

### Comparability Rule

```text
Cash break-even is meaningful only if both options satisfy the same behavior.

Meta is cheaper in a feasible use case when:
  Meta message charges + Meta-side operating costs
  < Wasender subscription + proxies + Wasender-side operating costs
```

Do not assign a financial value to Meta for a requirement it cannot satisfy, such as existing personal-group access. That is a feasibility failure, not a price premium.

## 5. Publicly Unresolved Facts to Validate Before a Decision

### WasenderAPI
