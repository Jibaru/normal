# Use type-prefixed opaque public handles

Expose stable public handles as a type prefix plus a 21-character NanoID-default-alphabet suffix matching `[A-Za-z0-9_-]{21}`: `con_`, `ctc_`, `grp_`, `cvs_`, `msg_`, `med_`, `snd_`, and `mca_` for connections, contacts, groups, conversations, messages, media, send operations, and MCP Authorizations. The random payload reveals neither provider identifiers nor creation time, the prefix prevents common cross-type mistakes, and deleted handles are never reused. A handle is always a name rather than a capability, so every call rechecks its owning User or current MCP Authorization, selected connection, scope, and object relationship as applicable; signed pagination cursors use a separate format.
