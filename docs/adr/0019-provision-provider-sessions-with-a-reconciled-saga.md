# Provision provider sessions with a reconciled saga

Create or return a durable Connection Setup from a browser-generated idempotency key and persist its provisioning intent before calling Wasender. The Setup reserves a dedicated platform-wide HMAC token for the normalized WhatsApp Number, distinct from connection-scoped lookup indexes, and its opaque identifier becomes the deterministic provider session name. A leased queue consumer asks the provider-control Worker to reconcile that marker before every attempt: adopt exactly one existing session, create only when none exists, and quarantine duplicates rather than blindly repeating an ambiguous create. Provider identifiers and encrypted per-session credentials are persisted before setup advances, while cancellation or expiry drives audited provider cleanup. The number remains reserved for a disconnected connection and throughout deletion or expired-setup cleanup, and is released only after provider-session removal is confirmed. This contains Wasender's lack of documented creation idempotency without placing the account-level PAT outside provider-control.
