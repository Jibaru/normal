# Do not retry ambiguous outbound sends

`send_text_message` validates its closed schema, current MCP Authorization, `messages:send` scope, and selected connection grant before resolving the same-authorization 90-day idempotency binding. An exact bound request returns its existing receipt even if connection or Directory state later changed; for schema-valid input on a currently granted requested connection, reuse with a different connection, recipient, or exact text returns `idempotency_conflict`. Only an unbound request then requires a `connected` connection, a contact or joined group marked active in the latest Directory projection, and available quota. The tool accepts no conversation handle, raw phone number, or provider identifier; text is one through 4,096 Unicode scalar values with at least one value outside Unicode 17.0 `White_Space` and is preserved without trimming or normalization, while the caller key matches `^[A-Za-z0-9_-]{21}$`.

One Neon transaction creates the Tool Call Log, Send Operation, idempotency binding, and quota reservation and sets `status = processing`, `attempt_claimed_at`, and `lease_expires_at = attempt_claimed_at + 30 seconds`. That atomic commit is the durable provider-attempt boundary: before it, failure rolls back the operation, binding, and quota and returns `isError`; after it, every outcome is an operation receipt and quota is never refunded. The Worker makes one 15-second Wasender call with no takeover or automatic retry. A complete direct response updates its causally bound operation; timeout, connection loss, crash, or lease expiry conservatively becomes `unknown`, while concurrent replays return current state without waiting or dispatching.

Pending Send Content is connection-encrypted and remains in active state only until the earliest of Stored Message creation, definitive pre-send failure, seven days after operation creation, the Message Retention Policy deadline, or Connection or Personal Account Deletion. A finite retention duration is measured from operation creation, while retain-until-deletion still leaves the seven-day pending-content cap. The 90-day binding retains only a domain-separated keyed fingerprint over the authorization, connection, recipient, and exact UTF-8 text bytes, allowing exact replay comparison without content recovery. Send Operation storage and replay protection have a 90-day maximum but remain callable only while the originating MCP Authorization is active; after ordinary expiry the key is unbound and reuse is a new send. Every invocation, including an exact replay or retry after preflight rejection, still requires Client Confirmation.
