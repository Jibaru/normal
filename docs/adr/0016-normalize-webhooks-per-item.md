# Normalize webhook deliveries per logical item

Persist each authenticated HTTP delivery as one encrypted Webhook Event, but split it into provider-neutral Webhook Items and normalize each item independently. One Neon transaction claims a connection-scoped, event-aware deduplication key and applies that item's domain writes plus durable outbox intents; stable provider identifiers are preferred, while events without one use an HMAC over canonical semantic fields, event kind, and provider timestamp or state. That semantic HMAC is only a Webhook Item retry-deduplication key: it never correlates a Send Operation, supplies provider message identity, or permits an outbound Stored Message to be created without its own trusted stable provider identifier. This lets retries safely skip duplicate items while committing new items even when Wasender regroups, reorders, or partially corrupts a batch, instead of making the raw delivery body the atomic or idempotent unit.
