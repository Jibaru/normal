# Use application-layer envelope encryption rooted in AWS KMS

Pending Send Content is an encrypted sensitive field bound to its account, connection, Send Operation, field purpose, and key version. User-chosen WhatsApp Connection names follow the same application-layer rule: Connection Setup storage uses its setup key and `connection-setup` / `display-name` context, activation decrypts after authorization and re-encrypts with the WhatsApp Connection key and `whatsapp-connection` / `display-name` context, and authorized browser or MCP reads decrypt only after access is established. Exact setup replay compares decrypted normalized names and does not retain a plaintext or keyed name fingerprint. Its seven-day active-state maximum is separate from the domain-separated, non-reversible request fingerprint retained with the 90-day idempotency binding.

Use one non-exportable AWS KMS symmetric content root key per environment and region to wrap random Personal Account keys; account keys wrap per-connection keys, and connection keys protect sensitive database fields and random per-media keys. One separate deletion-coordinator KMS key per environment and region protects only short-lived Deletion Capsules containing the provider identifiers needed after content-key erasure, with IAM and encryption-context policy preventing that role from decrypting tenant content. AES-256-GCM ciphertext includes a version and authenticated context binding it to the account, connection, record, field or media object, and key version. Operational IDs, timestamps, direction, content type, state, and verified Stored Media plaintext byte size remain integrity-protected and queryable; message content, provider payloads and identifiers, contact data, credentials, media filenames, normalized MIME types, and other media metadata are encrypted. Contact/group name prefixes of at least three characters and exact phone lookups use connection-scoped keyed blind indexes, accepting limited within-connection equality leakage instead of plaintext search columns or full-directory decryption. A provider identifier needed for send convergence is retained as ciphertext plus a connection- and identifier-namespace-scoped keyed exact-equality index for the Send Operation's 90-day life; the adapter canonicalizes each documented identifier type before indexing, and comparisons never cross namespaces. Stored Media is written to R2 as a versioned, chunked AES-256-GCM container so Workers can validate and decrypt bounded chunks without buffering an entire object and R2 never stores plaintext application data. Plaintext keys exist only in memory during an authorized operation; ciphertext records retain enough key-version metadata for rotation and rewrapping.
