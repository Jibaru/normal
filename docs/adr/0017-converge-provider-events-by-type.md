# Converge out-of-order provider events by type

A complete response to a Send Operation's own single provider call is causally bound to that operation and may set `accepted` or `failed` without a provider message identifier. It may establish an outbound Stored Message only when it also carries a trusted stable message identity shared with subsequent provider evidence and retained or response-carried content. Any independently delivered or later evidence may update a Send Operation only when it has the same WhatsApp Connection and an exact stable provider message identifier matched through the adapter's connection- and namespace-scoped equality index. Recipient, text, timestamps, status sequence, and apparent candidate uniqueness are never correlation evidence.

An authenticated outbound upsert may create or update a Stored Message only when the upsert carries its own trusted stable provider message identifier. ADR 0016's semantic HMAC fallback deduplicates Webhook Items only and never supplies message identity or correlates a Send Operation. Without exact shared identity, an upsert and Send Operation converge independently rather than being guessed together.

Public Send Status is `processing`, `accepted`, `sent`, `delivered`, `read`, `failed`, or `unknown` and converges by evidence strength rather than arrival order. Positive progress may skip stages and never regresses; `failed` may replace `processing`, `accepted`, or `sent` but not `delivered` or `read`; exactly correlated later positive evidence may correct `failed`; and `unknown` may reconcile to exactly correlated `accepted`, `sent`, `delivered`, `read`, or `failed`, never back to `processing`. Pending Send Content supplies text only while retained and only when no stronger content-bearing upsert or edit exists. After pending content expires, identity-only evidence updates the operation but does not create a readable Stored Message until a content-bearing upsert arrives within Message Retention Policy; the request fingerprint is never used to reconstruct text. Disconnection blocks new sends and expected ongoing ingestion but not already queued items or authenticated, exactly correlated late evidence for retained operations. For other records, deletion remains terminal, newer edits cannot be overwritten by older upserts, and snapshot-like Directory or connection changes compare provider occurrence time or version before verified receive order; conflicting source items remain temporarily in their encrypted Webhook Event for diagnosis.
