# Platform-manage Wasender sessions

The platform owns the Wasender accounts and credentials used to provision one provider session per WhatsApp Connection, so a User does not need a Wasender account or API key. Account-level PATs exist only in a private provider-control Worker and are restricted to provisioning and lifecycle operations; normal connection operations use the narrower session-specific credential. Provider message logging and automatic incoming-message reads are always disabled because the encrypted Message Store is the authoritative history and passive ingestion must not alter WhatsApp read receipts. Until vendor-approved enterprise capacity exists, onboarding stops at the documented session ceiling and uses a waitlist rather than unapproved account sharding or bring-your-own credentials. Production launch is contingent on written Wasender terms for enterprise session capacity, data processing and subprocessors, data deletion, security controls, webhook authentication and retries, because the public plans and documentation do not currently provide adequate guarantees for a scaled multi-tenant service.
