# Bootstrap tenant context with narrow database functions

Normal runtime roles have neither table-owner privileges nor `BYPASSRLS`. Narrowly scoped `SECURITY DEFINER` functions map a verified Clerk User or verified webhook ingress identity to one opaque Personal Account or WhatsApp Connection identifier; each subsequent transaction sets that identifier with `SET LOCAL`, and RLS plus composite tenant foreign keys enforce the boundary for every tenant-owned row. The functions use fixed `search_path` values, expose only the minimum identity lookup, and are executable only by the corresponding runtime role; privileged roles are reserved for migrations and audited deletion work. This closes the lookup-before-RLS bootstrap gap without weakening tenant isolation throughout the application.
