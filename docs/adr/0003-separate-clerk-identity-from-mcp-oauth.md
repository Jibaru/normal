# Separate Clerk identity from MCP OAuth

Use Clerk as the human identity provider and the Cloudflare API Worker as the OAuth authorization server and MCP resource server. The Worker uses Clerk authentication during authorization, then issues and validates its own resource-bound MCP tokens and enforces connection grants plus `connections:read`, `directory:read`, `messages:read`, and `messages:send` scopes. `list_connections` requires connection read; contact and group lists require Directory read; conversation lists, message reads, and Stored Media resources require message read; text sends and same-authorization send status require send. Every handler also checks the selected connection. Send permission never implies Directory or message-read permission, so a send-only caller can use a previously known recipient handle but cannot discover recipients or content. Consent renders in the Vercel app, requires Clerk reverification within five minutes, names an allowlisted MCP Client, requires separate unselected-by-default read-sharing and send-authority confirmations, and records an explicit set of WhatsApp Connections.

The Cloudflare OAuth library's required KV stores hashed or encrypted protocol artifacts, while Neon is authoritative for the MCP Authorization, scopes, selected connections, User/account status, and revocation. Every tool call, protected media resource read, and token refresh checks that current Neon state, so KV propagation does not extend application access after revocation. Access tokens expire after 10 minutes; one-time rotating refresh tokens expire after 30 days of inactivity and after a 90-day absolute authorization session, and refresh-token reuse revokes the token family. Send Operation retention is a 90-day storage and replay-protection maximum, not an access guarantee: replay and status require the originating MCP Authorization to remain active, and a later reauthorization does not gain access to an earlier authorization's operations. This preserves one User sign-in system while avoiding reliance on Clerk's currently undocumented custom-scope and exact MCP-resource audience behavior.
