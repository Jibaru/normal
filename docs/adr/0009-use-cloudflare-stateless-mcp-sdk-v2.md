# Use Cloudflare's stateless MCP SDK v2 stack

Implement the public `/mcp` endpoint with `agents/mcp/server` `createMcpHandler`, its exact-compatible `@modelcontextprotocol/server@2` release, and `@cloudflare/workers-oauth-provider`. The handler creates a fresh server per request, supports the July 2026 stateless protocol with legacy stateless compatibility, and receives verified OAuth context without Durable Object protocol sessions. Durable product state remains in Neon and R2 behind explicit authorized handles. Tool inputs and outputs use closed JSON Schema 2020-12 objects with explicit constraints. Successful calls return validated `structuredContent` and the same compact JSON in a text block for legacy clients, with optional protected `resource_link` blocks; actionable execution failures use `isError` and safe stable error codes, while JSON-RPC errors remain protocol/server failures. A send that has crossed its durable provider-attempt boundary returns a normal operation receipt even when its Send Status is `failed` or `unknown`; these are business outcomes, not tool execution errors. `send_text_message` and `send_pdf_file` advertise accurate standard risk hints and `_meta["anthropic/requiresUserInteraction"]: true` for supporting Claude clients, but have no self-asserted confirmation input or server elicitation because Client Confirmation is client UX rather than an independently verified security boundary. Sensitive fields are never mirrored through `x-mcp-header`, and response formats do not vary by detected client. Do not use `@ai-sdk/mcp`, which is an MCP client, deprecated `McpAgent`, or Vercel-specific server helpers for the Cloudflare data plane.
