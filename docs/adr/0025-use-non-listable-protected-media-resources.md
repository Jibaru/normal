# Use non-listable protected media resources

Identify ready Stored Media no larger than 16 MiB (`16,777,216` bytes) with `whatsapp-media://connections/{connection_id}/messages/{message_id}/media/{media_id}` and return concrete links from authorized message reads. Ready requires a non-null verified plaintext byte size and normalized MIME type; unknown MIME normalizes to `application/octet-stream`, inability to verify size makes processing `failed`, and filename may remain null. The verified byte size is an integrity-protected queryable operational field so eligibility, audit, and full-size quota reservation occur before content or encrypted metadata is decrypted. Ready media above that separate MCP-readable limit remains retained with its metadata but has no resource URI or link; message reads report `too_large_for_mcp` and the limit. This avoids base64 expansion against the Workers 128 MiB memory ceiling without lowering ingestion limits, adding chunk semantics, or issuing bearer URLs in the MVP. Advertise only the URI template and keep `resources/list` empty, avoiding a bulk media inventory. Every resource read strictly parses the URI, rechecks the current MCP Authorization and full ownership chain, durably audits and reserves bytes before decryption, and returns private non-cacheable binary content; unknown, unauthorized, mismatched, non-ready, and over-limit handles share one not-found boundary. Do not emit directly fetchable HTTPS, provider, public R2, or presigned URLs because they bypass or inconsistently carry MCP authorization.
