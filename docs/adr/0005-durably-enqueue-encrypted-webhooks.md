# Durably enqueue encrypted webhooks before acknowledgment

The Wasender webhook endpoint enforces a 1 MiB body limit, resolves a random non-enumerable ingress ID, verifies the unique per-connection secret, and requires any payload session ID to match the stored provider session before it returns success. It writes the original bytes as a connection-bound application ciphertext under a random key in a private R2 ingress bucket, then sends Cloudflare Queues only the opaque object ID, connection context, ciphertext hash, and receipt metadata. Success is returned only after both writes. If R2 succeeds but Queue fails, the endpoint returns failure and a sweeper re-enqueues unclaimed objects; provider and sweeper duplicates converge downstream. This single spool format avoids Queue's 128 KB message limit and keeps parsing in the public path to envelope verification. An at-least-once consumer stores and normalizes events idempotently in Neon and explicitly acknowledges successful items. Permanently invalid or unsupported items are durably quarantined without generic retries; transient Neon, KMS, or Worker failures receive seven jittered retries over roughly 21 hours before DLQ. An active DLQ consumer preserves the encrypted source, records the Ingestion Gap, and alerts operations before acknowledging it rather than relying on the DLQ's four-day unconsumed retention. Operator replay references an immutable source, creates an audited attempt, preserves original deduplication keys, and passes normal parsing and validation without payload editing. Original encrypted Webhook Events and quarantine references are retained for seven days to diagnose provider schema conflicts and ingestion failures, after which the R2 object is removed and only non-reversible deduplication fingerprints remain. The pipeline does not rely on provider ordering or retry guarantees.
